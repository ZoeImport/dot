# Bark 手机推送

用户指定的通知渠道是 Bark。使用 shell 调用本技能的脚本，手机通过苹果 APNs 接收通知。手机能否不开代理接收需在实际网络中验证；Bark API 成功仅表示接口接受，不证明手机已送达或解密成功。

## 本地配置发现

先检查环境变量 `BARK_CONFIG_DIR` 指定的目录；未设置时使用 `~/.config/bark-push/`。目录内需要两个私有文件：

- `device-key`：Bark App 生成的设备推送 key。
- `encryption-key`：与 Bark App 的 AES-128-CBC 设置一致的密钥，必须恰好 16 字节；推荐 16 位 ASCII，字符数不能代替 UTF-8 字节数。

目录权限为 `700`，文件权限为 `600`。可以通过 `bash scripts/send.sh --check` 无网络检查配置。运行脚本时将路径解析到本技能目录，不依赖当前工作目录。

如果配置不存在、不完整或校验失败，明确告诉用户缺少哪项，请用户提供或指定已有本地配置。先查本地，再询问；不要从历史聊天恢复凭据，不要静默生成替代密钥。用户授权生成新密钥时，将其保存到本地配置，并告知用户在 Bark App 同步设置。只有用户明确需要时才显示密钥。

密钥和设备推送 key 只保存在本机私有配置，不写入 Skill、脚本、示例、日志、仓库或 PR；不将私有配置复制到远端。迁移本技能到其它机器时，由该机器独立配置凭据。

## 发送

将 JSON 推送参数通过标准输入交给脚本。例如（参数无秘密）：

```bash
printf '%s' '{"title":"任务完成","body":"验证已通过，可以查看结果。"}' | bash /path/to/bark-push/scripts/send.sh
```

支持字符串 `title`、`body`、`sound`、`group` 和整数 `ttl`；默认 `sound=birdsong`、`group=codex`、`ttl=600`。正文写简短实际结果，避免凭据、私人原文或未验证的完成声明。参数通过 JSON 序列化传入，勿将动态内容拼入可执行 shell 语句。

脚本用 OpenSSL AES-128-CBC / PKCS#7 加密完整 JSON，每次生成新的 16 字节 ASCII IV；Base64 不换行，通过 `ciphertext` 与原始 `iv` 表单参数进行 URL 编码发送到 `https://api.day.app/`。不固定 IV，不截断密钥，不退回明文，不输出密文、推送 key 或密钥。

用户明确要求本次发送或为当前任务设置完成/失败通知后，按授权发送，无需逐条再次确认。仅询问“能否推送”不等于授权发送。该技能可自动选择，但不代表允许向其它收件人发送、通知所有未来任务或创建定时自动化。

成功时说明“Bark 接口已接受”；只有用户确认收到后才说明设备送达。失败时保留失败；请求超时可能已发送，不自动重发。需要用户设置手机密钥时，完成本地检查后等待其设置，再按授权发送测试消息。

延时通知需要执行环境在发送时仍然运行；本技能不保证电脑休眠、会话结束后继续执行。持续定时执行另按用户要求配置。

## 验证与依赖

运行依赖 Bash、Node.js、OpenSSL、xxd、curl；没有 Python 运行依赖。脚本提供配置、JSON、长度及服务响应检查，拒绝超长载荷而不截断内容。加密 JSON 上限 2048 字节，为 APNs 外层和 Base64 留出空间。

维护脚本时运行 `node --test scripts/send.test.mjs`。测试使用临时虚拟凭据和模拟 curl，独立解密请求验证内容、随机 IV 和失败行为，不向手机发送通知。

加密协议参考：[Bark 官方加密文档](https://bark.day.app/#/encryption)。AES-CBC 本身不提供认证标签，勿将此协议描述为具有消息认证的加密。
