# VPS Deploy

交付可验证的 VPS 代理服务和独立客户端配置。沿用用户指定的出口、分流规则和客户端，不把某次测速最优参数当作所有网络的默认值。

## 定位与选择

- 通过用户指定的 SSH alias 或私有主机清单连接；核实真实系统、架构、内存、带宽、监听端口、已有服务和客户端内核版本。截图与历史记录只是定位线索。
- 先区分客户端到 VPS、VPS 到目标、DNS、浏览器接口和静态资源的耗时。网页主文档的反爬 `403` 不能证明用户浏览器不可用；节点延迟也不能代表下载速度。
- 确认客户端支持 Hysteria2 且当前网络允许 UDP 后再测试它。经典 Clash 不等于 Mihomo；不要承诺所有 Clash 客户端兼容。
- 若用户要求“只保留一个最好”，先比较当前实际链路，再保留已验证方案。没有实测就说明候选及不确定性，不称“最快最安全”。

## 部署与安全边界

- 从官方发布选择适合目标架构和系统的版本，核对官方摘要或签名；不执行未经检查的一键脚本。保持管理 SSH 可用，不隐含重装系统、迁移账号或修改其他服务的授权。
- 配置使用独立随机认证密钥；服务以非登录专用用户运行，只授予所需权限。低端口通常只需 `CAP_NET_BIND_SERVICE`。旧 systemd 不一定支持 ambient capabilities，应核实实际进程 capability、文件权限和重启后的启动结果。
- 使用有效受信任证书，或通过可信渠道固定服务器证书的 SHA-256 指纹。不要用 `skip-cert-verify: true` 解决连接问题；指纹固定替代常规证书链验证，证书更新时也必须更新指纹。不要将 Mihomo 的客户端证书字段误用为服务端 CA 信任库。
- 对外仅开放所需端口；管理接口限制为本机。服务端按用途阻止代理访问回环、内网、链路本地和实例元数据地址；如需要内网代理则按用户需求设置例外。验证 ACL 时发送真实应用数据：SOCKS 成功响应可能早于上游连接，不能单独证明允许或拒绝成功。
- 若要求固定公网出口，核实服务端实际出站地址族和 IPv4 绑定；只关闭客户端 IPv6 并不能证明服务端不会从 IPv6 出口访问网站。
- 密码、私钥、订阅链接、完整运行配置只保存在主机或权限受限的本地目录，不进入技能、公共仓库、PR、日志或说明文档。共享技能包含流程和占位示例，不包含私有主机清单。
- 记录系统支持状态；新协议不能补救已停止安全维护的操作系统，不借优化任务自动重装。

## 独立配置与客户端适配

调整 Mihomo、Clash Verge 或 ClashMi 时读取 [references/mihomo.md](references/mihomo.md)。

遇到 DNS 检测出现国内解析器、手机与桌面结果不同，或调整 ClashMi 覆写时，读取 [references/dns-leaks.md](references/dns-leaks.md)。先核实实际生效配置与查询路径，再修改；保留用户的分流和 DNS 策略边界，不能承诺关闭一个开关就对所有网络零泄漏且零性能影响。

完整独立配置模板在 [assets/vps-server-usa.yaml](assets/vps-server-usa.yaml)，含 522 条分流规则。模板使用示例服务器、占位密码及全零证书指纹，不能直接连接；在私有输出中填写真实值。两个桌面进程路径里的 `LOCAL_USER` 也需按目标主机替换，iOS 上这些规则通常不会匹配。45 Mbps 只是样例带宽，不能作为其他网络的已验证值。用户自己的私有配置优先，模板不能覆盖其规则更新。

部署或换机前按 [references/host-validation.md](references/host-validation.md) 验证目标接口、实际客户端链路及服务器服务；接口不存在、未实测或只做了语法检查时，不报告服务验证通过。

- 独立配置和单独策略组是不同交付物。用户要求独立配置时，生成完整 YAML，保留原有 `rules` 数组的内容与顺序，仅改必要的节点和规则目标引用。
- 校验原配置与新配置的规则数组、DNS 策略及资源引用；有意变化逐项说明。不能只验证 YAML 语法，必须使用目标兼容内核检查加载结果。
- 检查应用的订阅源、全局 Merge、专属 Merge、脚本和生效配置。按单个配置设置覆盖，避免改变其他机场或用户配置。
- 保留证书指纹、DNS 出口和 UDP 转发能力。手机导出移除固定桌面网卡、桌面路由及无效本地路径，由手机客户端管理 VPN 隧道；需要特定平台优化时放在该客户端覆盖层。

## 以实测选择参数

- 使用同一目标和有界小文件做前后对比；记录下载字节、完成时间、首字节、超时及客户端和 VPS 的资源消耗。先检查 VPS 本身的目标访问，避免把源站慢当作代理慢。
- 隔离测试核验协议可用后，再测真实生效的客户端链路。临时 core、浏览器系统代理和已启用 TUN 可能走不同路径；只凭隔离测试不能宣布生产链路提速。
- 比较默认拥塞控制与按实测容量设置的带宽参数。Hysteria2 的 `up/down` 会影响拥塞控制选择，不盲填很大的数字，也不把一次家宽测出的速率照搬到蜂窝网络。
- 网卡绑定、UDP 缓冲区和 MTU 等只在证据指向它们时调整，记录影响范围。不要把累计重传计数写成当前丢包率，不把所有 socket 缓冲区都放大。
- 固定网卡可能改善桌面 TUN 路径，也可能破坏切网或移动端连接；优化值留在对应平台，跨平台导出避免固定网卡。

## 验证、清理与交付

1. 验证服务已启用、监听与运行用户正确，客户端配置加载成功且选中了目标节点。
2. 分别核验新建 HTTP 连接的公网出口、UDP/STUN 出口和 DNS 路径。代理协议支持 UDP 不代表浏览器 UDP 已被系统代理接管；移动端依赖实际 VPN 隧道。保留国内直连 DNS 的配置不能声称“全部 DNS 都在海外”。
3. 核验错误密码或错误指纹无法建立真实连接，并确认正确配置可用；测试节点只用于隔离探测，不留在用户分组里。原生 UDP/STUN 检查须排除直连规则的影响。
4. 热加载时保持已有 TUN、控制接口和监听参数；只关闭必要的旧测试连接，不为测速重置全部用户连接。
5. 若用户要求清理，仅删除本次创建且已不被引用的备份、临时 core、安装暂存和旧服务。先确认保留服务健康，再停用旧服务；不要删除运行中的证书、私钥、配置、SSH alias、其他订阅或用户备份。
6. 给出唯一主配置的绝对路径、SSH alias、实际协议和端口、验证结果及未验证部分。平台覆盖文件是适配层，不作为多个协议备选配置交付；手机客户端未实测时明确说明。
