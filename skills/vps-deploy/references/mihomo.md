# Mihomo、Clash Verge 与 ClashMi

## 保留分流和独立配置

定位应用当前选择的 profile UID、原始配置、覆盖层、最终生成文件和实际运行内核。不要按文件名猜测当前配置，也不要输出含凭据的完整配置。

修改节点和组时，比较解析后的 `rules` 数组及顺序；仅当用户要求修改分流时调整规则。保留被引用的 `rule-providers`、GeoSite/GeoIP 数据来源和策略组名称。进程或本地路径规则具有平台含义：桌面程序的规则可能在手机上永远不匹配，应说明差异，不能因此静默删除用户规则。

Clash Verge 的全局 Merge 或脚本可以覆盖导入文件里的 DNS。修改导出 YAML 后，还要读最终配置确认实际生效。针对独立 VPS profile 设置专属覆盖，保留其他机场原状。应用可能缓存 `profiles.yaml`，直接编辑元数据文件不等于应用已接受新状态；优先使用支持的应用操作或确认过的热加载方式。

## 热加载和控制 API

发现实际服务进程、用户及控制接口；特权服务和普通桌面 core 可能有不同 socket。不要硬编码历史路径。接口有认证时从私有配置安全读取，避免将认证信息写入命令行或输出。

- `/version` 确认实际运行内核；另一个二进制版本相同不等于其文件摘要相同。
- `/configs` 核对监听、模式和 TUN，不能据此假设获得了完整 DNS 配置。
- `/proxies` 与目标组的 `now` 核对实际节点选择。
- 使用目标版本支持的配置 API。若使用 `PUT /configs?force=true` 的 `payload` 热加载，应通过结构化 JSON 写入完整 YAML，避免手工转义；权限受限临时载荷用完删除。
- 重新读取状态，比较 TUN、模式和监听设置；成功状态码不代替新建连接的出口验证。

文件校验用实际兼容内核的 `-t -d DATA_DIR -f CONFIG`；数据目录需要所引用的 GeoSite、GeoIP 或规则资源。缺失资源与 YAML 错误分别处理，避免将验证动作变成不受控的下载或运行服务。

## DNS、隐私与延迟

分别量测冷解析和缓存命中。配置中的 DoH/DoT 是加密方式，不能证明 DNS 走了 VPS；检查解析连接所选策略和实际上游。Mihomo 支持在解析器 URL 后指定策略，例如 `#VPS-GROUP`，名称必须存在且目标版本支持。

对国外域名使用经代理的加密 DNS，同时按既有需求保留国内 CDN 的直连策略。不得把全局国内 fallback 无条件保留后仍声称代理域名没有国内解析，也不得为“零泄漏”静默破坏用户要求的国内分流。

检查代理节点域名的引导解析及循环依赖。`respect-rules`、解析器代理标记和代理服务器解析器不能互相循环；直接使用服务器 IP 时也需核对 DoH 域名的引导方式。不要因为一个配置用了某个开关，就机械推广到所有 DNS 架构。

系统 DNS 列表出现 ISP 不足以判定泄漏：若 UDP/TCP 53 已被 TUN 接管，实际请求可能已经被转发。用新随机域名、应用 DNS 日志或受控权威解析记录核验；明确国内分流属于有意直连还是非预期暴露。

## iOS ClashMi

[ClashMi 官方项目](https://github.com/KaringX/clashmi) 使用 Mihomo，并接受 YAML 配置；这不代表桌面网络参数也可移植。

- 保留 Hysteria2 认证、SNI、服务器证书指纹、分组、分流和兼容的 DNS 字段。
- 导出文件移除固定物理网卡，例如 `interface-name: en0`，以及桌面专用路由/隧道参数。即使 Wi-Fi 可用，也不能据此认定蜂窝和切换网络可用。
- 让 ClashMi 的 iOS VPN 扩展负责隧道，启用后再验证 HTTP、DNS 和 UDP。不要靠 HTTP 系统代理配置承诺接管 WebRTC。
- 测试 Wi-Fi 和蜂窝至少用户实际需要的一种网络；未拿到手机端结果，只报告配置已适配与本地内核校验，不能声称手机实测通过。
- 共享给手机的是私有配置文件，不是公开 GitHub raw 链接。传输可用 AirDrop 或用户指定的私有渠道，不把含认证的文件上传公共仓库。
- 手机链路容量可能低于固定 Hysteria2 带宽；若出现高延迟或掉速，应在该客户端测默认控制或下调速率，不回写其他平台已验证的参数。

参考：[DNS](https://wiki.metacubex.one/config/dns/)、[配置 API](https://wiki.metacubex.one/api/)、[出站通用参数](https://wiki.metacubex.one/config/proxies/)。
